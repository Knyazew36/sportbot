# Дропсет

## Context
Нужно добавлять дропсеты «а-ля суперсеты»: отметка в редакторе программы и цепочка в тренировке. Сейчас ни дропсетов, ни типов подходов нет. Суперсет — номер группы `superset` на `ComplexExercise`/`WorkoutExercise`, круг пишется одним листом (`RoundEntrySheet`), отдых после круга.

Решено с пользователем:
- План — флаг на упражнении комплекса + число сбросов: каждый подход = основной + N сбросов.
- В тренировке один лист на всю цепочку, отдых только после цепочки.
- Вес сбросов подсказывается, но все поля редактируются вручную.
- Охват: приложение, бот, история/статистика, шаблоны админа и импорт.

## Модель данных (Prisma)
Сброс — дочерняя запись подхода, а не отдельный `WorkoutSet`. Так `sets.length < plannedSets` (круги суперсета, `currentItem`, прогресс, полоса) остаётся верным без правок, а подход со сбросами пишется одной мутацией с одним `clientId` (офлайн-очередь и дедуп работают как есть).

```prisma
model ComplexExercise { ... drops Int @default(0) /// сбросов в каждом подходе; 0 — обычные подходы }
model WorkoutExercise { ... drops Int @default(0) /// снимок плана на старте }
model WorkoutSet      { ... drops WorkoutSetDrop[] }
model WorkoutSetDrop {
  id     Int @id @default(autoincrement())
  setId  Int
  set    WorkoutSet @relation(fields: [setId], references: [id], onDelete: Cascade)
  number Int            /// 1..n по порядку сброса
  weight Decimal @db.Decimal(6, 2)
  reps   Int
  @@unique([setId, number])
}
```
Миграция `..._drop_set` (накатывает пользователь, как и orval — см. память).

Правила (мой выбор, можно поправить):
- `drops` 0..3. Только для `measure = REPS` (на время сбросов нет).
- Дропсет и суперсет не совмещаем в v1: упражнение в суперсете не может иметь `drops > 0` (и наоборот — при вступлении в суперсет `drops` сбрасывается в 0). Валидация в сервисе + в импорте.
- В тренировке сбросы можно дописать к любому подходу кнопкой «+ сброс» даже при `drops = 0` в плане; план лишь задаёт, сколько строк открыть по умолчанию.

## Сервер
**Программа** (`apps/server/src/program/`):
- `dto/update-complex-exercise.dto.ts` — `drops?: number` (`@IsInt @Min(0) @Max(3)`).
- `program.service.ts` — апдейт упражнения пишет `drops` (проверка measure и суперсета в `where`/ошибке); `addExercises` с `joinItemId`/`newSuperset` обнуляет `drops`; копирование программы (~1051) и `replaceExercise` несут `drops`.
- Ответные DTO элемента комплекса — поле `drops`.
- `admin/admin-templates.controller.ts` — те же эндпоинты, проверить что идут через тот же сервис.

**Импорт** (`admin/import.service.ts`): `drops?: number` у элемента, проверка 0..3, только REPS, не в суперсете (рядом с `supersetError`), запись в create (~832).

**Тренировка** (`apps/server/src/workout/`):
- `workout.service.ts` `create()` (~921) — снимок `drops: item.drops`.
- `dto/create-workout-set.dto.ts` — `drops?: SetDropDto[]` (новый файл `dto/set-drop.dto.ts`: `weight`, `reps`; `@ArrayMaxSize(5)`, `@ValidateNested`).
- `dto/update-workout-set.dto.ts` — `drops?: SetDropDto[]`: замена целиком (`deleteMany` + `create` в одной транзакции).
- `dto/workout-set.response.dto.ts` — `drops: { weight, reps }[]`.
- `createSet` — nested `drops: { create: [...] }` в том же `workoutSet.create`; валидация каждого сброса `isValidSet`; для timed — ошибка, если сбросы пришли.
- `findItem`/`ownedSet` и все выборки подходов для ответа — `include: { drops: { orderBy: { number: 'asc' } } }`.
- `addSet` (бот) — парсинг цепочки: `60 10 / 45 8 / 30 8` (разделитель `/` или `→`); первый сегмент — основной, остальные — сбросы. Ошибка подсказывает формат, если у упражнения `drops > 0`.
- Логи: `log` при записи подхода со сбросами (`workoutExerciseId`, `drops=n`, `userId`).

**Тексты и статистика:**
- `workout.texts.ts` (57, 107, 275) — подход со сбросами: `60 кг × 10 → 45 × 8 → 30 × 8`; приглашение к вводу у дропсета показывает пример цепочки и «сбросов: 2».
- Объём `workout.service.ts:105`, `stats.service.ts` (434, 694–728), `stats-app.service.ts:332`, `workout-app.service.ts:446`, `workout-share.service.ts:121` — объём включает сбросы; рекорд/лучший подход и e1RM — только основной подход (сбросы легче, искажать не должны).
- `cooldown.service.ts` — нагрузка по мышцам считает подходы, сбросы не добавляют подход (мой выбор).
- `workout-timing.ts` — без изменений: цепочка = один подход.

## Фронт
После серверной части пользователь гоняет `api:generate`, затем tsc `-p tsconfig.app.json`.

**Редактор программы** (`widgets/program-editor/`):
- Там, где правятся sets/reps упражнения, — степпер «Сбросы 0–3» (скрыт для timed и для участников суперсета).
- `ComplexExerciseRow.tsx` — подпись, не бейдж (правило памяти): `3 × 8–12 · дропсет, 2 сброса`.
- `use-complex-editing.ts` — `drops` в оптимистичной правке; при сборке суперсета `drops → 0`.
- `entities/program` — хук апдейта несёт `drops`, `successMessage` уже есть/проставить.

**Тренировка** (`pages/workout/`):
- `SetEntrySheet.tsx` — если `item.drops > 0` или нажато «+ сброс»: под основной строкой строки «Сброс 1..n» (вес/повторы), кнопки «+ сброс» / удалить строку. Одна мутация `useAddSet` с `drops`.
- Подсказка веса (`entities/workout/lib.ts`, рядом с `roundPrefill`): сброс k = тот же сброс того же подхода из прошлой тренировки; иначе вес предыдущей строки −20%, округление до 2.5 кг (до 1 кг ниже 10 кг), повторы = повторы основной строки. Пересчитывается при изменении веса основной строки, пока пользователь не трогал строку сброса.
- `FocusSet`/`WorkoutActions` — подпись «Дропсет · 2 сброса»; отдых стартует после сохранения цепочки (одна запись = как сейчас).
- `widgets/workout/SetList.tsx` — строка подхода показывает цепочку `60 × 10 → 45 × 8 → 30 × 8`.
- `widgets/workout/EditSetSheet.tsx` — те же строки сбросов, `useUpdateSet` шлёт `drops`.
- `entities/workout/model/queue.ts` + оптимистичная вставка в `api.ts` (~169) — `drops` в переменных и в оптимистичном подходе.
- Экраны истории/статистики, использующие `SetList` или свой формат подхода, — та же цепочка.

## Проверка
1. `prisma migrate deploy` → сервер :4003 → `api:generate` (пользователь), tsc сервера и фронта (`-p tsconfig.app.json`). Prettier не запускать.
2. Редактор: поставить 2 сброса упражнению → подпись; собрать с ним суперсет → сбросы обнулились; timed — степпера нет.
3. Тренировка в приложении: подход со сбросами — подсказка −20%, ручная правка, «+ сброс», удаление строки; офлайн (сеть выкл.) → подход доезжает один раз.
4. Правка подхода в истории: изменить/удалить сброс.
5. Бот: `60 10 / 45 8 / 30 8` → цепочка в ответе; кривой ввод → понятная ошибка.
6. Статистика: объём вырос на сбросы, рекорд не сменился на сброс.
7. Импорт шаблона с `drops: 2` и с `drops` в суперсете (ошибка).
