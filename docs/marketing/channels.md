## 1. Каналы

### 1.1 Telegram-канал (`src_tgchannel`)

- **Роль в воронке:** Acquisition и немного Retention. Основной медиа-канал: объясняет механику, показывает технику и растяжки из справочника, даёт повод открыть бота. Конвертирует в Start у бота.
- **Формат:** один пост — одна мысль. Картинка по стилю бренда (бумага `#fff8f1`, тушь, один синий; крупная цифра или фраза Oswald, строка Onest) или скриншот экрана / реальный текст бота. Короткое видео 1080×1920 без звука. Текст поста до ~600 знаков, последняя строка — ссылка на бота.
- **Частота:** 3 поста в неделю (пн, ср, пт), 1 опрос или вопрос в неделю — внутри этих трёх. Больше не тянем: эксперимент 4 стратегии требует 3 поста в неделю.
- **Рубрики:**
  - «Техника» — одно упражнение из справочника: как делать, типичные ошибки (текст берётся из карточки справочника).
  - «Растяжка» — один комплекс или растяжка из справочника.
  - «Как работает» — одна функция продукта и скриншот: утренний/вечерний опрос, таймер отдыха, замена упражнения, очередь комплексов.
  - «Серия и пропуски» — пауза, предложение паузы на третьем пропуске, «напомнить завтра». Серия при пропуске начинается заново, об этом пишем прямо.
  - «Вместе» — друзья по ссылке, шаринг программы, итог тренировки.
  - «Обновления» — только то, что реально выпущено.
- **Голос-адаптация:** самый развёрнутый из каналов, но всё равно короткими предложениями. Допустим один абзац «зачем», один «как», одна строка CTA. Эмодзи: ✅ и не более одного на пост.
- **Чего НЕ делаем:** не придумываем технику и программы; не обещаем похудение, силу, результат; не публикуем вес и чужие тренировки; не называем цены; не сравниваем с конкурентами по именам; не пишем «ПОРВИ ЗАЛ», капс, подряд идущие «!»; не публикуем цифры пользователей без подтверждения владельца; не делаем ежедневные посты ради частоты.

### 1.2 MAX-канал (`src_max`)

- **Роль:** второй мессенджер, та же воронка. Дубль контента Telegram, ссылка на бота MAX.
- **Формат:** те же посты, что в Telegram, публикуются в тот же день со сдвигом в 1–2 часа. Картинки те же. Видео: **ПРОВЕРИТЬ** требования MAX к размеру и формату; по умолчанию загружаем тот же mp4.
- **Частота:** как Telegram (пн, ср, пт), без отдельного контента. Если ресурсов нет: приоритет пн и пт.
- **Рубрики:** те же. Отличается только ссылка и фраза в CTA: «Открой бота в MAX».
- **Голос-адаптация:** без отличий. Не пишем «в Telegram» в тексте, если пост общий; пишем «в мессенджере».
- **Чего НЕ делаем:** не копируем Telegram-ссылки; не обещаем функции, которых в MAX-версии нет (**ПРОВЕРИТЬ** по готовому коду при каждом новом обещании; кнопки «В сторис» пока нет вообще); не ведём отдельную редакцию.

### 1.3 Сторис пользователей (`src_story`)

- **Роль:** вирусный канал (Referral → Acquisition). Мы не публикуем сами, а делаем так, чтобы пользователю было просто выложить: карточки «Итог тренировки» и «Рекорд» 1080×1920 по `story-spec.md`.
- **Формат:** карточка из бота / Mini App (4 стиля), подпись «Спортбот» и имя бота на карточке. В сторис нет кликабельной ссылки для не-Premium, поэтому имя бота должно читаться на карточке.
- **Частота:** не контролируем. Наши действия: напоминание в канале раз в 2 недели («Как выложить итог»), реакция на найденные упоминания.
- **Рубрики:** нет. Есть рубрика «Вместе» в канале с примером карточки.
- **Голос:** на карточке одна цифра или короткая фраза Oswald, одна строка Onest. Текст карточки задан продуктом, не переписываем.
- **Чего НЕ делаем:** не просим «оставить отзыв за награду»; не репостим чужие сторис без явного согласия автора; не показываем на карточках вес тела (приватные данные); не публикуем счётчики «выложили столько-то сторис» без цифр из БД.
- **Зависимость:** метка `src_story` и события `story_created`, `story_shared`, `result_viewed` требуют доработки (стратегия 5.2). До неё эффект канала не измерить, фиксируем вручную: упоминания и новые пользователи по опросу «как узнал» (такого вопроса в онбординге нет, по `onboarding.service.ts` и шагам `pages/onboarding`; не добавляем).

### 1.4 Короткое видео: Reels / Shorts / сторис Telegram (`src_video`)

- **Роль:** Acquisition. Показ цикла «утро — вечер — серия» за 10–15 секунд (эксперимент 5).
- **Формат:** 1080×1920, 30 fps, без звука, шаблоны `apps/video` (Remotion). Текст вне верхних и нижних ~250 px. Вход резкий, выход короткий, «нажатие» только на цифры и достижения. Ссылка на бота — в описании профиля / подписи (под `src_video`, для каждого ролика `src_video_v01` … `src_video_v10`, как в `video.md`).
- **Частота:** 1 ролик в неделю с недели 2 календаря (всего 3 ролика, как в эксперименте 5, с разными первыми кадрами). Остальные сценарии `video.md` — запас на следующий месяц.
- **Площадки:** Telegram-канал и MAX (всегда); VK Клипы — если владелец заведёт VK-сообщество; Reels/Shorts — только кросспост, если аккаунты уже есть (по `video.md` раздел 1 Instagram в РФ без VPN недоступен). Вариант по умолчанию: не заводить новые аккаунты до результатов первых двух роликов в канале.
- **Рубрики** (как в `video.md`, раздел 3): «Бот говорит» (утро, вечер, пропуск, пауза), «Техника за 15 секунд», «Что будет, если…» (последствие вместо вдохновения). Ролики 1–3 календаря — V01, V02, V06 из `video.md`.
- **Голос:** только крупная цифра/фраза и одна строка. Субтитры не нужны (нет звука), текст читаем без звука.
- **Чего НЕ делаем:** без звука и озвучки с «мотивацией»; без лица бота; не показываем живые данные пользователей; не вставляем мигающие эффекты и градиенты; не смешиваем синий и малиновый в одном кадре.

### 1.5 Посевы в чатах и каналах (`src_<название_канала>`)

- **Роль:** платный/бартерный тест (эксперимент 6). Цель — узнать цену за активированного (онбординг + первая тренировка).
- **Формат:** готовый пост + ссылка с уникальной меткой. Текст в голосе бренда, без рекламной экзальтации.
- **Частота:** 3–5 размещений за 30 дней, не раньше 3-й недели календаря (после замера базы, эксперимент 0). Одновременно не больше одного.
- **Рубрики:** нет.
- **Бюджет:** **ПРОВЕРИТЬ.** Вариант по умолчанию: 0, ищем бартер (взаимные упоминания с тематическими каналами по залу/дому/растяжке). Если бюджет появится, лимит и список каналов утверждает владелец.
- **Метка:** на каждое размещение своя: `src_<короткое_название>` латиницей без пробелов.
- **Чего НЕ делаем:** не покупаем Telegram Ads до замера активации (стратегия 4.1); не делаем накрутку; не пишем в чужие чаты без разрешения администратора; не сравниваем с конкурентами; не называем цены.

Текст поста для посева (шаблон):

> Тренировка не теряется. Бот помнит план, подходы и серию за тебя.
> Утром скажет, что по плану. Вечером спросит, как прошло. Пропустишь день — бот запишет его и предложит напомнить завтра или поставить паузу.
> Открыть: `<ссылка с меткой>`

## 3. Правила сообщества и ответов

### 3.1 Общие принципы

- Отвечаем на «ты», коротко: одна мысль — одно предложение. Называем последствие и действие.
- Без хайпа, капса и «!!!». Эмодзи редко: ✅ как отметка.
- Не оправдываемся и не спорим; ошибку описываем без вины пользователя («Что случилось. Что делать»).
- Не публикуем ответы с личными данными, весом, чужими тренировками. Данные просим только в личных сообщениях бота и только то, что нужно для разбора.
- Не даём медицинских советов и не обещаем результат. Если вопрос про боль или травму: «Это вопрос к врачу, бот не заменяет врача» (дисклеймер уже есть в продукте).

### 3.2 Инбокс

- Окно ответа: 24 часа в будни (**ПРОВЕРИТЬ** кто ведёт; по умолчанию владелец). Выходные: ответы по возможности, критичное (бот не отвечает) — в приоритете.
- Включить комментарии под постами канала через чат-обсуждение **только если** есть человек, готовый модерировать (по умолчанию — выключено, чтобы не копить неотвеченное). Вместо этого: ссылка на личные сообщения владельца или форма обратной связи в приложении (когда она выкачена; **ПРОВЕРИТЬ у владельца** контакт поддержки).
- Категории: вопрос по функции, идея, баг, жалоба, спам. Для каждой есть заготовка ниже.

Заготовки:

| Тип | Ответ |
|---|---|
| Вопрос по функции | «Ответ в одно-два предложения. Если нужно, шаги: открой бота, нажми X. Если функции нет — так и говорим, обещаний нет» |
| Идея | «Записал. Передам в разработку. Сроков не обещаю» |
| Баг | «Спасибо, что написал. Чтобы найти причину, пришли: что нажал, что увидел, время. Данные не теряются, записанные подходы сохраняются» (последнее — только если подтверждено разработкой для этого случая) |
| Жалоба | «Понял, что не получилось. Вот что можно сделать сейчас: …. Если не поможет, разберу вручную» |
| Спам / реклама | Удалить без ответа. Повтор — бан |
| Вопрос про цену | «Сейчас про тарифы ничего не скажу» (пока нет ответа владельца по монетизации) |

### 3.3 Негатив

1. Не удаляем критику по существу. Удаляем только оскорбления, спам, данные третьих лиц.
2. Отвечаем один раз, по делу: что понято, что делаем, что можно сделать сейчас.
3. Не вступаем в публичный спор. Если не помогло — переносим в личные сообщения.
4. Критика конкурентов в ответах не используется.
5. Повторяющиеся жалобы (3 и более на одну тему за неделю) идут в разработку списком с ссылками на сообщения.

### 3.4 Кризис «бот не ответил»

Проблема: бот не прислал утренний/вечерний вопрос, не ответил на команду, Mini App не открывается. Это бьёт по главному обещанию (бот приходит сам).

| Шаг | Действие |
|---|---|
| 1. Сигнал | 2 и более сообщений за час в канале/личке или проверка вручную: бот не отвечает. Проверяет ведущий канала, эскалирует разработке |
| 2. Подтверждение | Разработка проверяет, массовое ли это. Пока причина не ясна, публично не обещаем сроки |
| 3. Первое сообщение (в течение 1 часа после подтверждения) | «Бот сейчас отвечает с перебоями. Разбираемся. Записанные подходы не потеряются. Как только заработает, напишу здесь» (последнее предложение про данные — **ПРОВЕРИТЬ у разработки**, верно ли для этого сбоя; иначе убрать) |
| 4. Пока сбой | Раз в 2–3 часа короткий статус, одной фразой. Если новостей нет: «Пока без изменений» |
| 5. Восстановление | «Бот работает. Что было: …одной строкой. Если вопрос не пришёл, открой /today: там тренировка на сегодня. Вчерашний день можно поправить за 7 дней: /history» (оба пути есть в боте, `menu.bot.ts`, `plan.bot.ts`) |
| 6. После | Разбор в разработке, пост в канале только если сбой был виден многим. Серия: по коду день без ответа через сутки закрывается пропуском сам (`PlanCronService`), серия обнулится; пользователь может исправить отметку за 7 дней (/history). Компенсация за сбой — решение владельца, не публичное обещание |

Пауза контента: во время сбоя плановые посты канала откладываются (рекламные CTA «Открыть бота» не публикуем).

### 3.5 Приватность и согласие

- Скриншоты пользователей публикуем только с явного письменного согласия, без имён, веса и ников друзей.
- Для примеров используем тестовый аккаунт с вымышленными данными (без выдуманных «отзывов»).

## 5. Недельный ритм измерений

Цели не фиксируем: «калибровать после 2 недель замеров» (стратегия 5.2). Метрики берём из стратегии. Многие пока без источника: вместо них временно используем нативную статистику площадки и ручной подсчёт (последний столбец).

День недели: понедельник, 30 минут. Результат — одна строка на канал в таблице и 1–2 решения.

| Канал | Что смотрим | Откуда | Пока нет трекинга — как считаем |
|---|---|---|---|
| Telegram-канал | Подписчики (прирост), просмотры постов за 24 ч, пересылки, переходы по ссылке | Нативная статистика канала | Старт по `src_tgchannel`: после доработки из БД (`acquisitionSource`); до этого — число Start у бота за неделю по логу бота, если он есть (**ПРОВЕРИТЬ**) |
| MAX | Подписчики, просмотры, переходы | Нативная статистика MAX (**ПРОВЕРИТЬ**) | Доля Telegram/MAX среди новых пользователей: `telegramId` / `maxId` (есть в БД, стратегия 5.2) |
| Видео | Просмотры, досмотры, клики по ссылке | Статистика площадки | Один из трёх вариантов должен быть в 2 раза лучше худшего по кликам (критерий эксперимента 5) |
| Сторис пользователей | Упоминания, `story_created`, `story_shared`, `result_viewed` | События (после доработки) | Ручной поиск упоминаний; значение в таблице «вручную» |
| Посевы | Старт по метке, цена за Акт | Рекламная статистика размещения + БД | Цена = затраты / число активированных; до трекинга — только Start из статистики поста |
| Все каналы (воронка) | Новые пользователи, онбординг, первая тренировка за 7 дней | `User.createdAt`, `SportProfile.onboardedAt`, `Workout` (есть) | SQL-отчёт эксперимента 0 |
| Продукт (контекст) | WAT, W2/W4, ответы на вечерний опрос | `Workout`, `StretchSession`, `PlanDay` (есть) | SQL |
| Реферальные | Инвайтов создано / принято | `FriendInvite`, `Friendship` | Принято — только после добавления связи (`acceptedBy`, стратегия 5.2): принятый инвайт сейчас удаляется |

Правила чтения:
- При малой выборке (десятки пользователей) смотрим на тренд и разбираем причины в интервью, а не на значимость (стратегия 6).
- Решения по формату поста принимаются, если у формата не менее 3 публикаций.
- Раз в 2 недели: пересмотр целей (по стратегии, после замеров), выбор топ-2 формата (эксперимент 4).
- Что не считаем: K-фактор — до появления данных; Revenue — до ответа владельца по монетизации.

Блокеры для измерения (задачи разработке, не в этой фазе): поле источника из `start=src_*`, слой событий `AnalyticsEvent`, дата блокировки бота (флаг уже пишется из `my_chat_member` в `User.data`), связь «инвайт принят». Полный список — в `README.md`.
