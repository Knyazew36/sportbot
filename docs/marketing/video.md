# Спортбот: короткое видео (эксперимент 5 из strategy.md)

Основа: `docs/marketing/strategy.md` (раздел 6, эксперимент 5; раздел 7, контракт), `packages/brand/BRAND.md` (Голос, Движение, Видео), шаблоны `apps/video` и `packages/render-contract/src/compositions.ts`. Тексты бота и функции продукта взяты оттуда же и из strategy.md, не придуманы. Что есть в коде, сверено в ноябре 2026; что решает владелец или площадка, помечено **ПРОВЕРИТЬ**. Цифры в раскадровках (подходы, секунды, вес) — **пример**: в ролик идут значения из реального экрана или справочника. Код в рамках этой задачи не менялся.

Ограничения: вставки без звука, 1080×1920, 30 fps, текст вне верхних и нижних ~250 px, Oswald (цифры, фразы) + Onest (пояснение), один синий акцент на кадр, без хайпа и капса, «очередь комплексов», не «ротация». Лица, абстрактные графики и вес тела не показываем.

Один источник (kod.ru, июль 2026) говорит об ограничении работы, без подробностей. ## 2. Десять сценариев

Общие правила. Хук — в первые 1–2 с, крупный текст Oswald в безопасной зоне (между 250 и 1670 px по вертикали). Длительность 10–15 с. Последние 2–3 с — CTA (заставка). Метка: `src_video`; чтобы различать ролики, каждому свой `src_video_v01` … `src_video_v10`. Проверено по коду: бот разбирает `fr_` и `ln_` по первому сегменту до `_`, `src_…` игнорирует, суффикс допустим (латиница, цифры, `_`, `-`, до 64 знаков); сохранение метки в БД — задача разработке. Метрики по strategy.md, 5.2: клики/новые по источнику, онбординг, первая тренировка, приглашения.

Условные названия шаблонов. Есть сейчас: `lower-third` (плашка: название до 60 символов, подпись до 60, заливка mint/rest/blue/rose, 3/5/7 с, фон paper/transparent/chroma), `end-card` (заставка 2/3/4 с). Нужны новые: **Poster** (крупная фраза или цифра Oswald + строка Onest, жест «нажатие»), **BotChat** (сообщения бота и ответ пользователя, нажатие кнопки), **Counter** (цифра считает вверх/вниз), **Rows** (строки появляются, активная выделяется), **RefCard** (фото упражнения из справочника + 2–3 строки), **ScreenFrame** (запись экрана приложения в кадре с учётом безопасных зон). Подробности в разделе 4.

### V01. Бот приходит сам
- Хук (0–2 с): Poster «Утром бот скажет, что по плану» (Oswald), без синего.
- Раскадровка: 0–2 хук; 2–6 BotChat: утреннее сообщение бота о плане дня; 6–10 BotChat: вечерний вопрос «как прошло», нажатие кнопки ответа (синий акцент — на кнопке); 10–12 Poster «Тренировка засчитана ✅»; 12–15 CTA.
- Тексты бота — реальные из `poll.service.ts` и `workout.texts.ts`: утром «Доброе утро. Сегодня тренировочный день — будешь тренироваться? Следующая по программе: «{комплекс}».» (кнопки «Да» / «Нет», в боте с эмодзи), вечером «Потренировался сегодня?», после «Да» «Тренировка «{комплекс}» засчитана ✅» и «Серия: N». Эмодзи кнопок в кадре можно опустить, текст сообщений не менять. Комплекс и серию брать с демо-аккаунта.
- Шаблон: нужен новый — BotChat + Poster. CTA: `end-card`.
- Метрика: новые по `src_video_v01`, онбординг.

### V02. Три пропуска подряд
- Хук: Poster «Пропустил три тренировки подряд?»
- Раскадровка: 0–2 хук; 2–6 BotChat: бот на третьем пропуске предлагает паузу (текст бота: «Три пропуска подряд. Поставить бота на паузу?»; конец «Серия сохранится.» в кадр не берём: к третьему пропуску серия уже обнулена, `recalcStreak`); 6–10 Poster «Пауза — вместо срыва. Дни паузы пропусками не считаются» (последствие и выбор, как велит голос); 10–12 кнопки «пауза» / «напомнить завтра» нажатием; 12–15 CTA.
- Шаблон: нужен новый — BotChat. CTA: `end-card`.
- Метрика: онбординг и W2 (ролик про удержание), вторично возврат после предложения паузы (эксперимент 7).

### V03. Подходы записываются сами
- Хук: плашка «Жим лёжа — подход 3» на записи экрана (название упражнения брать из справочника, пример).
- Раскадровка: 0–2 ScreenFrame с записью экрана: ввод веса и повторов; 2–8 запись идёт, поверх `lower-third` с названием упражнения и подписью «подход × повторы» (значения с экрана); 8–12 плашка уходит, видно «записано»; 12–15 CTA.
- Шаблон: `lower-third` есть (фон `transparent`, накладывается поверх записи экрана). Запись экрана снимается отдельно (без людей, без звука); рамка ScreenFrame — желательная доработка, без неё можно кадрировать вручную.
- Сверено: карточка упражнения показывает прошлый результат с датой, а ввод подхода даёт подсказку по прошлому подходу (`ExerciseCard.tsx`, `SetEntrySheet.tsx`, `item.last`). Это можно показывать, значения брать с демо-аккаунта.
- Метрика: клики, первая тренировка.

### V04. Таймер отдыха
- Хук: Counter, крупный отсчёт отдыха на заливке `rest`.
- Раскадровка: 0–2 хук «Отдых» + цифра; 2–8 отсчёт (в примере 60 → 0, значение из экрана); 8–10 нажатие на «ноль» (punch); 10–12 Poster «Следующий подход»; 12–15 CTA.
- Шаблон: нужен новый — Counter (+ Poster). CTA: `end-card`.
- Метрика: клики, первая тренировка.

### V05. Очередь комплексов
- Хук: Poster «Сегодня комплекс Б, завтра В».
- Раскадровка: 0–2 хук; 2–7 Rows: три комплекса из реальной программы, активный подсвечен синим; 7–10 строка «сделан», подсветка переходит на следующий (`nextComplexId`); 10–12 Poster «Бот помнит очередь за тебя»; 12–15 CTA.
- Слово — «очередь», не «ротация». Название комплексов брать из шаблонной программы справочника, не придумывать (в BRAND «День А» бейджем не оформляем: подписью).

### V06. Рекорд
- Хук: Counter «Новый рекорд» с цифрой, жест «нажатие».

### V07. Позови напарника

## 3. Три серийные рубрики (из шаблонов, без людей)

Каждая рубрика — один шаблон, меняется только JSON props; файлы собираются пакетом.

1. **«Бот говорит»** (BotChat + `end-card`): 12 с, одно реальное сообщение бота и ответ. Темы: утро, вечер, пропуск, пауза, офлайн. Тексты берутся из кода бота как есть, поэтому голос не расходится с продуктом. Нужна проверка актуальных формулировок.
2. **«Техника за 15 секунд»** (RefCard + `lower-third` + `end-card`): одно упражнение или растяжка из справочника; название, 2–3 строки техники и одна частая ошибка. Источник — справочник, не выдумка. Подходит и для каналов, и для VK Клипов.
3. **«Что будет, если…»** (Poster + Counter): последствие вместо вдохновения. Примеры: «Если пропустить три раза — бот предложит паузу», «Если нет сети — подходы сохранятся». Каждая серия — один факт продукта, который можно проверить в приложении.

Частота на старт эксперимента, как в `channels.md`: 1 ролик в неделю с недели 2, рубрики чередуются; после трёх роликов оставить лучшую по замерам.

## 5. Чек-лист публикации и замеры

Перед публикацией:
- [ ] Ролик 1080×1920, 30 fps, без звука (если площадка требует дорожку, добавить тишину, а не музыку).
- [ ] Текст вне верхних и нижних ~250 px, один синий акцент на кадр, нет смешения синего и малинового.
- [ ] Хук в первые 1–2 с, он читается без звука; пояснение — одной строкой Onest.
- [ ] Все факты (тексты бота, срок ссылки, офлайн) сверены с кодом; нет цен, нет цифр пользователей, нет медицинских обещаний, нет веса тела и чужих тренировок.
- [ ] Обложка: первый кадр — Poster с хуком, читается в сетке профиля, без мелкого текста.
- [ ] Подпись: 1–2 коротких предложения голосом бренда («Бот помнит план, подходы и серию за тебя») + ссылка на бота с `src_video_*`. Эмодзи не более одной отметки.
- [ ] Хэштеги: 3–5, по теме (тренировки, зал, дом, растяжка); в Telegram их можно не ставить. Список хэштегов и общий тон не из конкурентов.
- [ ] Время: гипотезы — утро перед тренировкой или вечер после работы; тестируем два слота, статистика по слотам решает. Данных по аудитории нет (**ПРОВЕРИТЬ**).
