# Спортбот — SEO-пакет лендинга

Источники: `apps/landing/docs/brief.md`, `docs/marketing/copy.md`. Факты о продукте только оттуда, ничего не добавлено.

Плейсхолдеры, которые нужно заменить до выката:
- `https://example.com` — домен лендинга (во всех блоках ниже).
- Ссылки на ботов (`{BOT_TG}`, `{BOT_MAX}`) в SEO-блоках не используются, в JSON-LD их нет сознательно: имя бота не подтверждено.
- Цена: «бесплатно» (FAQ 6) не подтверждено владельцем, поэтому в разметке нет `offers` и вопроса про цену.

Данных о частотности нет (Wordstat, Search Console и Метрика недоступны). Запросы ниже собраны по продукту и намерению. Частоты проверить в Яндекс Wordstat до финализации, это блокер для приоритизации, но не для вёрстки.

## 4. JSON-LD

Выбор типа: `SoftwareApplication` с `applicationCategory: SportsApplication`. `MobileApplication` не берём: продукт не распространяется через сторы, а работает как бот и Mini App внутри мессенджера. Это честнее для разметки и не нарушает правило «разметка = видимый контент».

Что намеренно не включено:
- `offers`/`price: 0`: цена не подтверждена (FAQ 6).
- `aggregateRating`/`review`: отзывов и цифр нет.
- Ссылки на ботов: имя не подтверждено. Когда будет, добавить в `url`/`installUrl` (без `?start=`-метки).
- `Organization`/`publisher`: нет данных об юрлице и поддержке.

Тексты ответов FAQ дословно соответствуют copy.md 1.3 (вопросы 1–5). Если правите текст в вёрстке, правьте и здесь, иначе разметка расходится с видимым контентом.

Важно по ожиданиям: Google с 2023 года показывает расширенный сниппет FAQ только для авторитетных государственных и медицинских сайтов, поэтому визуального эффекта в Google не ждать. Для Яндекса и для понимания страницы разметка полезна, вреда нет.

## 5. Canonical, язык, theme-color, favicon

`<html lang="ru">` обязателен. Блок для `<head>` целиком (порядок: charset и viewport первыми):

```html
<!doctype html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Спортбот: трекер тренировок в Telegram и MAX</title>
  <meta name="description" content="Бот-трекер тренировок в Telegram и MAX. Утром пишет, что по плану, вечером спрашивает, как прошло. Помнит подходы и серию. Установка не нужна.">
  <link rel="canonical" href="https://example.com/">
  <meta name="robots" content="index, follow, max-image-preview:large">

  <meta name="color-scheme" content="light dark">
  <meta name="theme-color" content="#fff8f1" media="(prefers-color-scheme: light)">
  <meta name="theme-color" content="#070d1a" media="(prefers-color-scheme: dark)">

  <link rel="icon" href="/favicon.svg" type="image/svg+xml">
  <link rel="icon" href="/favicon-32.png" type="image/png" sizes="32x32">
  <link rel="icon" href="/favicon-16.png" type="image/png" sizes="16x16">
  <link rel="apple-touch-icon" href="/apple-touch-icon.png" sizes="180x180">
</head>
```

Замечания:
- Значения theme-color взяты из брифа: светлая `--brand-paper` #fff8f1, тёмная `color.dark.paper` #070d1a.
- Файл `apple-touch-icon.png` — это `export/apple-touch-icon-180.png`, переименованный; размер 180×180 (проверить).
- Тёмная тема знака (кремовый треугольник) делается внутри `favicon.svg` через `@media (prefers-color-scheme: dark)` в `<style>`, как в образце `apps/frontend/public/favicon.svg`.
- Яндекс подхватывает `favicon.ico` из корня. Если не нужен ICO, ничего страшного: Яндекс также читает `link rel="icon"`, но иконка может появиться в выдаче позже. Если важен быстрый показ, положить `favicon.ico` (32×32) в корень, ссылку не добавлять.
- Пути с ведущим `/` предполагают, что лендинг на корне домена. Если он лежит в подпапке, поменять на относительные.
- Одна каноническая версия: выбрать вариант с `www` или без, и сделать 301 с другого, а также с `http` на `https`. Это настройка хостинга, а не HTML.

## 6. robots.txt и sitemap.xml

`robots.txt` (корень сайта):

```
User-agent: *
Allow: /

Sitemap: https://example.com/sitemap.xml
```

Заметки: закрывать нечего (в лендинге нет админки и параметров). Директива `Host` для Яндекса больше не нужна. После выката добавить сайт в Яндекс Вебмастер и Google Search Console, отправить sitemap, указать регион и главное зеркало. Метки `?start=` стоят только на внешних ссылках на ботов, на индексацию лендинга не влияют.

`sitemap.xml`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://example.com/</loc>
    <lastmod>2026-11-17</lastmod>
    <changefreq>monthly</changefreq>
    <priority>1.0</priority>
  </url>
</urlset>
```

`lastmod` обновлять при реальных правках контента. `changefreq` и `priority` Google игнорирует, Яндекс учитывает как подсказку; оставлены безвредно. Политика конфиденциальности и условия, когда появятся, добавляются в sitemap отдельными `url`.

## 7. Скорость

Цель: LCP < 2.5 с, INP < 200 мс, CLS < 0.1 на мобильном (4G, от 375px). Лендинг статичный, так что цели достижимы без хитростей.

### Шрифты (Oswald, Onest; Cormorant)

- Хостить самим, не с Google Fonts: меньше запросов и без зависимости от внешнего домена (в РФ внешние шрифтовые CDN бывают нестабильны). Проверить, что в `tokens.css` нет `@import` на внешние шрифты; если есть, заменить на локальные `@font-face`.
- Формат только `woff2`. Подмножества: кириллица + латиница. Для Oswald и Onest — variable-файлы, оставить только оси и диапазон веса, которые реально используются в вёрстке (какие — определить по CSS, не брать «на всякий случай»).
- Пример подсета (fonttools):

```
pyftsubset Oswald-Variable.ttf --flavor=woff2 --layout-features='*' ^
  --unicodes="U+0020-007E,U+00A0-00FF,U+0400-04FF,U+2010-2015,U+2018-201E,U+2022,U+2026,U+2116,U+00AB,U+00BB" ^
  --output-file=oswald-cyr-lat.woff2
```
  Тот же набор для Onest. Знаки ««», «№», «—» и «×» оставить, они используются в текстах.
- `@font-face` с `font-display: swap` и `unicode-range` (если разбиваете кириллицу и латиницу на два файла, браузер скачает только нужные):

```css
@font-face {
  font-family: "Oswald Variable";
  src: url("/assets/fonts/oswald-cyr-lat.woff2") format("woff2");
  font-weight: 200 700;
  font-style: normal;
  font-display: swap;
}
```
  Имена семейств и диапазон веса сверить с `tokens.css` (там имена с суффиксом `Variable`).
- Preload только двух файлов, которые нужны для первого экрана: Oswald (H1, hero) и Onest (Lead, кнопки). Preload обязательно с `crossorigin`, даже для своего домена:

```html
<link rel="preload" href="/assets/fonts/oswald-cyr-lat.woff2" as="font" type="font/woff2" crossorigin>
<link rel="preload" href="/assets/fonts/onest-cyr-lat.woff2" as="font" type="font/woff2" crossorigin>
```
- Cormorant курсивом — одна подпись на страницу: не preload. Либо подсет только под символы этой подписи, либо системный serif-запасной. Загружается лениво по факту использования.
- Против сдвига при подмене шрифта: у fallback-шрифта подобрать `size-adjust`, `ascent-override` и `descent-override` под Oswald и Onest (`@font-face` с `src: local("Arial")`), чтобы заголовок не прыгал.

### Картинки

- Hero-макет телефона — вероятный LCP-элемент. Не `lazy`: `fetchpriority="high"`, `decoding="async"`, явные `width`/`height`. Preload в `<head>` добавлять только если это `<img>`, а не CSS-фон:

```html
<link rel="preload" as="image" href="/assets/hero-phone-540.avif" type="image/avif" fetchpriority="high">
```
  Имя файла условное: заменить на реальное.
- Промо 2–8 (исходник 1080×1920, соотношение 9:16): на странице показываются примерно 240–320 CSS-пикселей по ширине. Отдавать `srcset` 360/540/720 по ширине (проверить реальную раскладку) и формат avif с webp-запасным, PNG не использовать. Целевой вес: до 60–90 КБ на кадр на 540 по ширине.
- Всем картинкам: `width` и `height` из реального соотношения (для промо `width="540" height="960"`), плюс CSS `aspect-ratio` и `height: auto`. Это убирает CLS.
- Ниже первого экрана: `loading="lazy"` и `decoding="async"`. Лента-свайп: первые 1–2 кадра ближе к экрану — тоже lazy, но без `fetchpriority`.
- `alt` у каждого кадра осмысленный и без повтора ключевика: например «Экран тренировки: подходы и таймер отдыха». Alt писать по тому, что реально на кадре (сверить с файлом).
- Логотип и знак — SVG инлайном или одним файлом, без растра. `og.png` на странице не нужен, он только для превью.

<img src="/assets/promo-3-set-540.webp"
     srcset="/assets/promo-3-set-360.webp 360w, /assets/promo-3-set-540.webp 540w, /assets/promo-3-set-720.webp 720w"
     sizes="(min-width: 768px) 320px, 70vw"
     width="540" height="960" loading="lazy" decoding="async"

### CSS, JS, сеть

- Критический CSS (hero + шрифты + токены) инлайном или одним маленьким файлом; остальное можно отложить. Лендинг без фреймворка-рантайма: JS нужен только для свайп-ленты и, если нужно, подстановки ссылок на ботов из конфига. FAQ на нативном `details`, без JS.
- Без аналитики, чатов и виджетов, которые блокируют основной поток. Если подключать Метрику, `defer`/`async` и после первой отрисовки.
- Анимации только `transform`/`opacity` (нажатие кнопки по брифу, `translate` + тень), уважать `prefers-reduced-motion`. Тень на `box-shadow` не анимировать по размытию (у нас размытия нет, жёсткая тень).
- Включить сжатие brotli/gzip, `Cache-Control: public, max-age=31536000, immutable` для файлов с хэшем в имени (шрифты, картинки, CSS), короткий кэш для `index.html`. HTTP/2 или HTTP/3 на хостинге.
- Тёмная тема на CSS-переменных: без повторной загрузки ресурсов и без мерцания, `color-scheme` в `<head>` уже задан выше.
