❯ а как мы получать id группы будем?                                            

● Два разных источника, не путать.

  vk_group_id из launch-параметров — только если мини-апп открыт внутри
  сообщества (кнопка приложения в самом сообществе). Если педагог открыл апп из
  каталога/личного профиля — параметра нет. И даже если есть — это просто число,
  для отправки сообщений бесполезно: нет токена с правом messages.

  Для рассылки реально нужен community access token с правом messages. Получить
  его без разрешения на автоматизацию у VK нельзя — только сам владелец
  сообщества создаёт вручную:
  Управление сообществом → Работа с API → Ключи доступа → Создать ключ → 
  отметить "Сообщения сообщества".

  Дальше твой сценарий подключения (в настройках Organization):
  1. Педагог вставляет в форму этот токен.
  2. Бэк дёргает groups.getById с этим токеном (без параметра group_id) — VK сам
     вернёт id/название того сообщества, к которому токен привязан. Так
     получаешь vkGroupId — не спрашиваешь его руками, риск ошибки/фейкового id
     отпадает.
  3. Токен (шифрованно) + vkGroupId сохраняешь в Organization.
  4. Отдельно там же педагог включает Callback API: Работа с API → Callback API
     → вставляет твой /vk/callback, копирует «код подтверждения» и «секретный
     ключ» — тоже в форму, тоже per-Organization.

  vk_group_id из launch-параметров можно использовать как бонус —
  автоопределение «из какого сообщества сейчас открыли апп» (для UI/контекста),
  но не как замену токену.

  Хочешь — сделаю сейчас: поля
  vkCommunityToken/vkCallbackSecret/vkConfirmationCode в Organization + эндпоинт
  подключения (принимает токен → groups.getById → сохраняет).
