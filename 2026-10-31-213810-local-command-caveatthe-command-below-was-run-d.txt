❯ Какие еще формулы есть для спортсменов? вот у нас есть  1пм, что нам еще в    
  приложении может пригодиться?                                                 

● Есть 1ПМ. Что ещё полезно, по пользе для приложения:

  Силовые (из данных подходов, считаются сами)
  - Тоннаж = вес × повторы × подходы. Уже есть в итогах тренировки. Добавить
    недельный и по группам мышц.
  - Относительная сила = 1ПМ / вес тела. Сравнивать людей разного веса.
  - Коэффициенты Уилкса / DOTS / IPF GL: сила с поправкой на вес тела и пол.
    Нужны для рейтингов и сравнения с другими.
  - RPE/RIR → % от 1ПМ: по таблице RPE при 5 повторах и RPE 8 выходит ≈ 77% от
    1ПМ. Позволяет подсказывать вес на следующую тренировку.
  - Рабочий вес из % 1ПМ: для программ вида «5×5 по 80%».
  - Прогрессия (двойная): все подходы закрыты на верхней границе повторов,
    значит +2,5 кг. Автоподсказка «в прошлый раз 60×10, сегодня 62,5».
  - Объём на группу мышц в неделю (подходов на группу). Ориентир 10–20 подходов,
    это самая полезная аналитика.
  - Стагнация / дилоад: 1ПМ не растёт 3–4 недели, значит предложить разгрузочную
    неделю.

  Состав тела и питание
  - ИМТ: слабая метрика для спортсменов, но все ждут.
  - BMR (Миффлин–Сан Жеор): базовый обмен = 10·вес + 6,25·рост − 5·возраст ±
    5/161.
  - TDEE = BMR × коэффициент активности (1,2–1,9). Отсюда цель по калориям.
  - БЖУ: белок 1,6–2,2 г/кг, жиры ≥0,8 г/кг, остальное углеводы.
  - % жира по US Navy: по обхватам шеи, талии, бёдер. Нужны замеры.
  - Сухая масса = вес × (1 − %жира).
  - Вода: ~30–35 мл/кг.

  Кардио
  - Пульс макс: 208 − 0,7·возраст (Танака). Старая 220 − возраст менее точна.
  - Зоны пульса по Карвонену: ЧСС резерва = макс − покой, зоны от неё.
  - VO₂max: тест Купера (12 минут бега) или по пульсу покоя (15 × макс/покой).
  - Темп/скорость, калории по MET: ккал = MET × вес × часы.
  - Прогноз результатов (Ригель): время на 5 км → прогноз на 10 км или
    полумарафон.

  Восстановление и нагрузка
  - ACWR: нагрузка за 7 дней / среднее за 28. Зона 0,8–1,3 безопасна, выше 1,5
    растёт риск травм.
  - Session RPE = RPE × минуты. Простая мера нагрузки без датчиков.
  - Монотонность и напряжение (Фостер): перетренированность.
  - HRV/пульс покоя: тренд, готовность к тренировке.

  Что я бы взял первым (максимум пользы, минимум вводных)
  1. Объём подходов на группу мышц в неделю: данные уже есть.
  2. Подсказка веса из RPE + 1ПМ: «сегодня 62,5 × 8».
  3. Относительная сила и DOTS: для рейтингов и мотивации.
  4. Детектор стагнации с предложением разгрузки.
  5. Калории/БЖУ (BMR+TDEE): если в приложении есть профиль (вес, рост,
     возраст).

  Какие данные профиля у нас уже собираются? Скажи, посмотрю по коду, что из
  этого реально считается без новых полей, и распишу, куда встраивать.

● Проверил схему. Из того, что нужно, почти всё уже есть.

  Уже есть

  - WorkoutSet: weight, reps, doneAt.
  - ExerciseMuscle с ролью PRIMARY / SECONDARY.
  - e1rmOf (Эпли) в packages/api/lib/stats.ts.
  - BodyWeight (история веса тела).
  - SportProfile.gender (nullable) и timeZone.

  1. Объём подходов на группу мышц в неделю

  Новых данных не нужно, миграции нет.
  - Запрос: WorkoutSet → WorkoutExercise → Exercise → ExerciseMuscle,
    группировка по muscleId и неделе.
  - Подсчёт: PRIMARY = 1 подход, SECONDARY = 0,5. Это общепринятая
    договорённость, её стоит показать в подсказке.
  - Фильтры: только done, только упражнения с повторами (секундные не считаем),
    неделя считается в timeZone пользователя.
  - Вопрос по замене: считать exerciseId (что реально сделано), а не
    replacedExerciseId.
  - Где: новый блок в stats (сервер + локальный read-stats в мобилке), виджет в
    widgets/stats/.
  - Объём работы: небольшой.

  2. Подсказка веса по RPE и 1ПМ

  Здесь нужна новая колонка, и она тянет за собой много работы.
  - RPE в схеме нет. Нужно WorkoutSet.rpe (nullable, Decimal(3,1)) и миграция.
  - Ввод RPE в UI подхода: веб и мобилка, это самый затратный кусок.
  - Синк: DTO, orval, локальная БД мобилки и офлайн-очередь (clientId-подходы
    уже ходят через неё).
  - Расчёт: таблица RPE × повторы → % от 1ПМ, вес = e1rm × %.
  - Дешёвый вариант без RPE: двойная прогрессия по истории. Если в прошлый раз
    все подходы закрыли repsMax, предложить +2,5 кг, иначе тот же вес. Данные
    уже есть, миграция не нужна.
  - Мой совет: сначала дешёвый вариант, RPE позже, когда понятно, что людям
    нужна подсказка.

  3. Относительная сила и DOTS

  - Относительная сила = e1rm / последний BodyWeight. Всё есть, считается на
    лету.
  - Для DOTS не хватает трёх вещей:
    a. Пол: gender nullable и сейчас нужен для расцветки. Для тех, у кого он
       null, надо спросить или не показывать DOTS.
    b. Сумма трёх (присед + жим + тяга): в Exercise нет пометки «это базовое».
       Нужно поле или список id, и нужны все три лифта в истории.
    c. Коэффициенты DOTS: константы в packages/api/lib/.
  - Подвох с приватностью: в схеме BodyWeight помечен «не отдаётся ни друзьям,
    ни группе». Рейтинг среди друзей по относительной силе позволяет вычислить
    вес тела. Нужно решить: показывать только свой результат или выставлять
    коэффициент без веса.

  Порядок

  1. Объём по мышцам (самое дешёвое, без миграции).
  2. Относительная сила на странице упражнения.
  3. Прогрессия по истории (без RPE).
  4. DOTS, после решения по приватности и «базовым» упражнениям.
  5. RPE.
